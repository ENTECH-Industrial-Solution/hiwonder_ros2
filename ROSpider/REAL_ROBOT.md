# ROSpider บนหุ่นจริง (สถานีหุ่นจริง ช่วงบ่าย)

ไทย | [English](REAL_ROBOT.en.md)

คู่มือนี้สำหรับวิทยากร ใช้คู่กับ [README.md](README.md) (simulation) ช่วงเช้าผู้เรียนทำโจทย์ในซิม ช่วงบ่ายเอาคำตอบจากซิมไปลองบนหุ่นจริง

## 1. ภาพรวม

- **บนหุ่นรันโค้ดของ Hiwonder ที่มากับ image ของหุ่น ไม่ใช่แพ็กเกจซิม** หุ่นใช้ ROS 2 Humble บน Jetson โค้ดอยู่ใน `/home/ubuntu/ros2_ws` ไม่ต้องติดตั้งหรือ build อะไรเพิ่ม
- **คำสั่ง launch ชื่อเดียวกับในซิม** ต่างกันแค่ชื่อแพ็กเกจ เช่นในซิมใช้ `rospider_gazebo apriltag_track.launch.py` บนหุ่นใช้ `example apriltag_track.launch.py`
- **ตัวตรวจอัตโนมัติ (`check_*.py`) ใช้บนหุ่นไม่ได้** เพราะอ่านตำแหน่งจริงจาก Gazebo บนหุ่นให้วิทยากรตัดสินตามเกณฑ์ในคู่มือนี้แทน โดยใช้เทปบนพื้นช่วยให้ตัดสินได้ชัด
- **แนวคิดของโจทย์บนหุ่น: "คำตอบจากซิมใช้กับของจริงได้แค่ไหน"** ไม่ต้องตั้งค่าผิดไว้ให้แก้ ของจริงจะพาไปเจอปัญหาเอง ทั้งแสงในห้อง หน่วยของระยะ และความคลาดของหุ่น
- **คำสั่งในคู่มือนี้อ่านมาจากโค้ด Hiwonder ในรีโปนี้ ยังไม่ได้ลองรันบนหุ่นจริง** ช่วงเช้าให้ซ้อมไล่ครบทุกข้อบนหุ่นหนึ่งรอบก่อน (หัวข้อ 3)

## 2. เตรียมก่อนวันสอน

อุปกรณ์:

| อุปกรณ์ | จำนวน | ใช้กับ |
|---|---|---|
| ลูกบาศก์สีแดง เขียว น้ำเงิน ขนาดราว 3–5 ซม. (ขนาดเดียวกับที่หุ่นหยิบได้ในชุด) | สีละ 1–2 | โจทย์ 1, 2 |
| ลูกบาศก์สีส้มหรือชมพู (ของหลอกที่สีใกล้แดง) | 1 | โจทย์ 1 |
| กล่องกระดาษสูงราว 30 ซม. (ทำเงา) | 1 | โจทย์ 1 |
| แท่นวางของสูงเท่าที่ track_and_grab ของ Hiwonder ใช้ | 1 | โจทย์ 2 |
| ถาดหรือกล่องรับของ | 1 | โจทย์ 2 |
| ป้าย AprilTag แบบ tag36h11 หมายเลข 1, 2, 3 (ใช้ป้ายที่มากับชุดหุ่น หรือพิมพ์ขนาดเท่ากัน) | 1 ชุด | โจทย์ 3, ภารกิจ |
| เทปสีติดพื้น, ตลับเมตร | 1 | ทุกข้อ |
| กล่องกระดาษทำผนังห้อง A/B และประตู (แบบห้อง maze ในซิมแต่ย่อลง) | ตามพื้นที่ | ภารกิจ |
| แบตเตอรี่สำรองที่ชาร์จเต็ม | อย่างน้อย 1 | ทุกข้อ |

งานเตรียม:

1. **เข้าหุ่นจากเครื่องวิทยากรได้** ผ่าน NoMachine (เห็นหน้าจอหุ่น ต้องใช้กับหน้าต่าง LAB_Tool) หรือ SSH
2. **สำรองไฟล์สีไว้** ใช้คืนค่าระหว่างเปลี่ยนกลุ่ม
   ```bash
   cp ~/software/lab_tool/lab_config.yaml ~/lab_config.backup.yaml
   ```
3. **สร้างแผนที่สนามภารกิจไว้ล่วงหน้า** ตามคู่มือ Hiwonder (`ros2 launch slam slam.launch.py` แล้วบันทึกแผนที่) อย่าให้แต่ละกลุ่มสร้างเอง เพราะจะกินเวลาหุ่นหมด
4. **`ROS_DOMAIN_ID` ของโน้ตบุ๊กผู้เรียนต้องไม่ตรงกับของหุ่น** เพราะซิมบนโน้ตบุ๊กก็ส่ง `/controller/cmd_vel` เหมือนกัน ถ้าเลขตรงกันและอยู่ Wi-Fi เดียวกัน หุ่นจริงจะเดินตามคำสั่งจากซิม
5. **ติดเทปบนพื้น**: จุดเริ่มของหุ่น (มีลูกศรบอกทิศ), จุดวางลูกบาศก์ของโจทย์ 1, แท่นกับถาดของโจทย์ 2, ตำแหน่งป้ายของโจทย์ 3

## 3. ซ้อมช่วงเช้า (30 นาที)

ไล่โจทย์ 1–3 และภารกิจบนหุ่นหนึ่งรอบตามหัวข้อ 5–6 จดทุกอย่างที่ไม่ตรงกับคู่มือนี้ เช่น ชื่อคำสั่ง ตำแหน่งไฟล์ หรือระยะที่หุ่นหยุด แล้วแก้คู่มือก่อนเริ่มสอน สิ่งที่ต้องวัดเก็บไว้:
- หุ่นหยุดห่างป้าย AprilTag กี่ซม. (ใช้เป็นเฉลยของคำถามในโจทย์ 3)
- ระยะที่ track_and_grab หยิบได้ (ใช้ติดเทปตำแหน่งแท่นในโจทย์ 2)

## 4. เริ่มต้นทุกครั้งที่เปลี่ยนกลุ่ม

บนหุ่น (NoMachine หรือ SSH):

```bash
sudo systemctl stop start_app_node.service
```

คำสั่งนี้หยุดโปรแกรมที่หุ่นเปิดเองตอนบูต (ของแอปมือถือ) ไม่งั้นจะชนกับเดโมที่เปิดเอง จากนั้น:
1. วางหุ่นบนจุดเริ่ม หันตามลูกศร
2. คืนไฟล์สีจากสำเนา
   ```bash
   cp ~/lab_config.backup.yaml ~/software/lab_tool/lab_config.yaml
   ```
3. ดูแบตเตอรี่ ถ้าหุ่นเริ่มเดินไม่มั่นคงให้เปลี่ยนแบต

แต่ละโจทย์เปิดโปรแกรมของตัวเอง **ปิดของโจทย์ก่อน (Ctrl+C) ทุกครั้งก่อนเปิดโจทย์ถัดไป** เพราะ launch ของ Hiwonder แต่ละตัวเปิดกล้องและตัวควบคุมหุ่นเอง ถ้าเปิดซ้อนกันจะชนกัน

## 5. โจทย์บนหุ่นจริง (กลุ่มละ 20 นาที)

### โจทย์ 1 จูนสีใต้แสงจริง (8 นาที)

**จัดฉาก**: วางลูกบาศก์แดง เขียว น้ำเงิน และของหลอกสีส้มบนจุดที่ติดเทปไว้หน้าหุ่น ใช้กล่องบังให้ลูกน้ำเงินอยู่ในเงา

**คำสั่ง** (บนหุ่น เปิด 2 terminal):
```bash
ros2 launch peripherals depth_camera.launch.py
```
```bash
python3 ~/software/lab_tool/main.py
```

**ขั้นตอน**:
1. เปิดค่าสีแดงจากซิมบนโน้ตบุ๊ก (`~/.ros/color_challenge_tuned.json` หรือ `config/color_challenge.yaml`) แล้วตั้ง slider ของสีแดงใน LAB_Tool ให้เท่ากัน
2. ดูช่อง mask จะเห็นว่าค่าจากซิมจับไม่ครบ หรือจับเกินใต้แสงจริง
3. จูนแดง เขียว น้ำเงินใหม่ทีละสี แล้วกด **Save** (บันทึกลง `lab_config.yaml` ซึ่งโจทย์ 2 ใช้ต่อ)

**เกณฑ์ผ่าน** (ดูจากช่อง mask ทีละสี) เหมือนในซิม:
- ด่าน 1: mask ของแต่ละสีเห็นลูกบาศก์ของสีนั้นครบ
- ด่าน 2: mask สีแดงไม่เห็นของหลอกสีส้ม
- ด่าน 3: mask สีน้ำเงินยังเห็นลูกที่อยู่ในเงา

**คำถามปิด**: ทำไมค่าจากซิมใช้ไม่ได้? ในซิมแสงคงที่และสีเรียบ ของจริงมีแสงหลายทิศ เงา และกล้องปรับแสงเอง

### โจทย์ 2 หยิบของ (6 นาที)

**จัดฉาก**: วางลูกบาศก์บนแท่นที่ติดเทปไว้ในระยะที่หุ่นหยิบได้ (วัดไว้ตอนซ้อม) วิทยากรเลือกสีเป้าหมาย

**คำสั่ง** (เปลี่ยน `blue` เป็นสีที่วิทยากรบอก):
```bash
ros2 launch example track_and_grab.launch.py color:=blue start:=true
```

**เกณฑ์ผ่าน**:
- ด่าน 1: กล้องหันตามลูกสีที่สั่ง ไม่ใช่สีอื่น
- ด่าน 2: แขนหยิบลูกบาศก์ขึ้นได้
- ด่าน 3: วางลงถาดได้โดยไม่ตก

โจทย์นี้ใช้ช่วงสีที่กลุ่มเพิ่งจูนในโจทย์ 1 ถ้าจูนไม่ดีจะพังตั้งแต่ด่าน 1 ผู้เรียนจะเห็นว่าแต่ละส่วนต่อกัน

### โจทย์ 3 AprilTag (4 นาที)

**จัดฉาก**: ติดป้ายหมายเลข 1, 2, 3 ไว้ข้างหน้าหุ่น ห่างกันป้ายละราว 40 ซม. และห่างจากจุดเริ่มราว 1 ม.

**คำสั่ง**:
```bash
ros2 launch example apriltag_track.launch.py target_tag:=2
```

**เกณฑ์ผ่าน**:
- ด่าน 1: หุ่นเดินไปหาป้ายหมายเลข 2 ไม่ใช่ป้ายอื่น
- ด่าน 2: หุ่นหยุดหน้าป้ายโดยไม่ชน

**คำถามปิด**: วัดด้วยตลับเมตรว่าหุ่นหยุดห่างป้ายกี่ซม. แล้วเทียบกับ 0.35 ม. ในซิม
- บนหุ่นจริง ระยะหยุดเขียนตายไว้ในโค้ดของ Hiwonder (`d_stop = 15`) ปรับผ่านคำสั่งไม่ได้
- หน่วยของมันไม่ใช่เมตร แต่เป็นหน่วยที่ตัวตรวจจับป้ายของ Hiwonder คำนวณเอง
- บทเรียน: ค่าเดียวกันแต่คนละหน่วย ต้องวัดเทียบของจริงก่อนใช้

## 6. ภารกิจปิดท้ายบนหุ่นจริง (ทุกกลุ่มร่วมกัน 20 นาที)

ทำตอนท้ายวัน ให้กลุ่มที่ทำภารกิจในซิมได้ดีที่สุดมาสั่งหุ่นต่อหน้าทุกคน

**ต่างจากในซิม** เพราะโค้ดของ Hiwonder บนหุ่นทำได้ไม่เท่าเวอร์ชันซิม:
- ใช้ป้ายเดียวกับบล็อกเดียว
- สั่งทีละขั้นด้วยมือ ไม่มีไฟล์ภารกิจให้รันอัตโนมัติ
- track_and_grab ของ Hiwonder หยิบแล้ววางข้างตัวทันที ถือบล็อกเดินกลับไม่ได้ ภารกิจบนหุ่นจึงจบที่การหยิบ

**ขั้นตอน** (ปิดคำสั่งเก่าด้วย Ctrl+C ก่อนเปิดคำสั่งถัดไปทุกครั้ง):
1. **Nav2 ไปห้อง B**
   ```bash
   ros2 launch navigation navigation.launch.py map:=<ชื่อแผนที่สนาม>
   ```
   ใน RViz ใช้ **2D Goal Pose** คลิกจุดหมายในห้อง B ตามพิกัดที่กลุ่มเขียนไว้ในไฟล์ภารกิจของซิม
2. **เดินหาป้ายที่ถูก**
   ```bash
   ros2 launch example apriltag_track.launch.py target_tag:=<หมายเลข>
   ```
3. **หยิบบล็อก**
   ```bash
   ros2 launch example track_and_grab.launch.py color:=<สี> start:=true
   ```

**เกณฑ์ผ่าน**:
- ด่าน 1: ถึงห้อง B
- ด่าน 2: หยุดหน้าป้ายที่ถูก
- ด่าน 3: หยิบบล็อกสีที่ถูกได้

**คำถามปิด**: ลำดับขั้นที่เขียนในซิมใช้กับของจริงได้แค่ไหน? ขั้นไหนต้องแก้ และแก้เพราะอะไร

## 9. ปัญหาที่พบบ่อย

- **หุ่นขยับเองหรือไม่ยอมทำตามคำสั่ง**: ยังไม่ได้หยุด `start_app_node.service` หรือยังมีคำสั่งของโจทย์ก่อนค้างอยู่ ให้ปิดให้หมดแล้วเริ่มใหม่
- **หุ่นเดินตามคำสั่งจากซิมบนโน้ตบุ๊ก**: `ROS_DOMAIN_ID` ของโน้ตบุ๊กตรงกับของหุ่น ให้เปลี่ยนเลขที่โน้ตบุ๊ก
- **กลุ่มใหม่จับสีแปลกๆ**: ลืมคืนไฟล์สี (หัวข้อ 4)
- **หุ่นเดินโซเซหรือทรุด**: แบตอ่อน ให้เปลี่ยนแบต
- **หยิบไม่ถึง**: แท่นอยู่ไกลกว่าระยะที่วัดไว้ตอนซ้อม ให้ย้ายแท่นกลับไปที่เทป
